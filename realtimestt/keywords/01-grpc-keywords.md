# gRPC 관련 키워드

## gRPC 기본 개념

### Remote Procedure call (RPC)
원격 프로시저 호출. 네트워크를 통해 다른 서버의 함수를 마치 로컬 함수처럼 호출할 수 있게 해주는 통신 방식입니다.

### gRPC가 요구 하는 것
gRPC는 Protocol Buffers(protobuf)를 사용하여 서비스와 메시지를 정의해야 합니다. .proto 파일에 서비스 인터페이스를 정의하고, 이를 통해 클라이언트와 서버 코드를 생성합니다.

## gRPC 통신 패턴

### Unary
일반적인 요청-응답 패턴. 클라이언트가 하나의 요청을 보내고 서버가 하나의 응답을 반환합니다.

### Server streaming
서버 스트리밍. 클라이언트가 하나의 요청을 보내면 서버가 여러 개의 응답을 스트림으로 전송합니다.

### Client streaming
클라이언트 스트리밍. 클라이언트가 여러 개의 요청을 스트림으로 보내고 서버가 하나의 응답을 반환합니다.

### Bidirectional Streaming
양방향 스트리밍. 클라이언트와 서버가 독립적으로 여러 메시지를 주고받을 수 있습니다.

### 멀티 플렉싱
하나의 연결에서 여러 gRPC 호출을 동시에 수행할 수 있는 기능입니다. HTTP/2의 멀티플렉싱을 활용합니다.

## gRPC Python 라이브러리

### grpcio
gRPC의 Python 구현 라이브러리입니다. gRPC 서버와 클라이언트를 Python으로 개발할 수 있게 해줍니다.

### grpcio-tools
gRPC 개발 도구 모음입니다. protoc 컴파일러와 Python 플러그인을 포함하여 .proto 파일에서 Python 코드를 생성할 수 있습니다.

## gRPC 구성 요소

### stub
gRPC 클라이언트에서 서버의 메서드를 호출하기 위한 프록시 객체입니다. 서버의 서비스 정의에 따라 자동 생성됩니다.

### channel
gRPC 클라이언트와 서버 간의 연결을 나타냅니다. 호스트와 포트 정보를 포함하며, 여러 stub이 하나의 channel을 공유할 수 있습니다.

## STT 결과 상태

### interim
중간 결과. STT 처리 중 아직 최종 확정되지 않은 임시 인식 결과입니다.

### final
최종 결과. STT 처리가 완료되어 확정된 최종 인식 결과입니다.
