# 실시간 STT 시스템 개요 및 파일 목록

## 학습 목표

이 문서를 통해 다음을 학습할 수 있습니다:

1. 실시간 STT 시스템의 전체 아키텍처와 데이터 흐름을 이해합니다
2. 각 구성 요소의 역할과 책임을 파악합니다

4. 완전한 실시간 음성 인식 시스템을 구현할 수 있습니다

## 시스템 개요

실시간 STT(Speech-to-Text) 시스템은 사용자가 말하는 음성을 실시간으로 텍스트로 변환하는 시스템입니다. 이 시스템은 다음과 같은 특징을 가집니다:

- **실시간 처리**: 오디오 스트림을 받는 즉시 STT 처리를 수행합니다
- **양방향 통신**: WebSocket을 통한 실시간 데이터 교환
- **스트리밍 변환**: 오디오 형식 변환과 STT 처리를 동시에 수행합니다
- **비동기 처리**: 여러 작업을 동시에 처리하여 성능을 최적화합니다

## 전체 아키텍처 파이프라인

```
┌─────────────┐

│  (저장 및 관리)      │
└──────┬──────────────┘
       │ 오디오 데이터
       ▼
```

## SessionContext 패턴 (Context Object Pattern)

실시간 STT 시스템은 **Context Object Pattern**을 사용하여 세션 상태를 관리합니다. 이 패턴은 다음과 같은 장점을 제공합니다:

### 불변성(Immutability)의 장점

- **상태 동기화 문제 해결**: 상태값을 직접 참조하는 대신 불변 객체를 전달하여 동시성 문제 방지
- **예측 가능한 동작**: 상태 변경이 명시적으로 새로운 객체 생성으로 표현됨
- **디버깅 용이**: 각 상태 변경 시점의 컨텍스트를 추적 가능

### SessionContext 구조

```python
@dataclass
class SessionContext:
    """실시간 STT 세션 컨텍스트"""
    session_id: UUID
    session: Session
    base_path: str
    input_format: str
    language_code: str
    interim_results: bool
    metadata: dict[str, Any]
    start_time: datetime
    config: dict[str, Any]
    chunk_count: int
    sequence_number: int
    
    def increment_chunk_count(self) -> "SessionContext":
        """청크 개수를 증가시킨 새로운 컨텍스트 반환"""
        return SessionContext(...)  # 새 객체 생성
```

### 상태 업데이트 패턴

상태를 변경할 때는 기존 객체를 수정하는 대신 새로운 객체를 생성합니다:

```python
# ❌ 나쁜 예: 직접 상태 수정
context.chunk_count += 1  # 동기화 문제 발생 가능

# ✅ 좋은 예: 새 컨텍스트 생성
context = context.increment_chunk_count()  # 불변성 보장
```

### Redux와의 비교

SessionContext 패턴은 Redux와 유사한 원칙을 공유하지만, 구현 방식과 사용 범위에서 차이가 있습니다.

#### 공통점

두 패턴 모두 **불변성(Immutability)**을 핵심 원칙으로 합니다:

1. **상태 동기화 보장**: 불변성을 통해 여러 곳에서 동시에 상태를 수정하는 문제를 방지
2. **예측 가능한 동작**: 상태 변경이 항상 새 객체 생성으로 명시적으로 표현됨
3. **디버깅 용이성**: 각 상태 변경 시점의 상태를 추적 가능
4. **비동기 환경 안전성**: 불변성을 통해 비동기 환경에서도 상태 동기화 문제 방지

#### 차이점

| 항목 | Redux | SessionContext |
|------|-------|----------------|
| **아키텍처** | 중앙화된 스토어 (Single Source of Truth) | 컨텍스트 객체 직접 전달 |
| **상태 변경 방식** | 액션(Action) → 리듀서(Reducer) → 새 상태 | 메서드 호출 → 새 컨텍스트 반환 |
| **비동기 처리** | 미들웨어(Thunk/Saga)를 통한 비동기 액션 | 비동기 함수 내에서 직접 새 컨텍스트 생성 |
| **사용 범위** | 전역 상태 관리, 복잡한 상태 로직 | 세션별 컨텍스트, 단순한 상태 전달 |
| **의존성** | 스토어에 의존 (dispatch, getState) | 컨텍스트 객체를 파라미터로 전달 |

#### Redux 예시

```javascript
// Redux: 액션 기반 상태 변경
const incrementAction = { type: 'INCREMENT_CHUNK_COUNT' };

function reducer(state, action) {
  switch (action.type) {
    case 'INCREMENT_CHUNK_COUNT':
      return { ...state, chunk_count: state.chunk_count + 1 };
    default:
      return state;
  }
}

// 비동기 처리: Redux-Thunk
const incrementAsync = () => (dispatch, getState) => {
  setTimeout(() => {
    dispatch(incrementAction);
  }, 1000);
};
```

#### SessionContext 예시

```python
# SessionContext: 메서드 기반 상태 변경
context = context.increment_chunk_count()  # 새 컨텍스트 반환

# 비동기 처리: 비동기 함수 내에서 직접 처리
async def handle_audio(context: SessionContext) -> SessionContext:
    # 오디오 처리 후 새 컨텍스트 반환
    new_context = context.increment_chunk_count()
    return new_context
```

#### 대전제

**불변성(Immutability)이 상태 동기화의 핵심 원칙**입니다:

- 상태 변경은 항상 새 객체 생성으로 표현되어야 함
- 기존 객체를 직접 수정하면 동시성 문제 발생 가능
- 불변성을 통해 비동기 환경에서도 안전한 상태 관리 가능

실시간 STT 시스템에서는 **SessionContext 패턴이 더 적합**합니다:

- 단일 세션 컨텍스트만 관리하면 되므로 중앙화된 스토어가 불필요
- 컨텍스트 객체를 직접 전달하여 명시적이고 간단한 상태 관리
- 비동기 함수 내에서 직접 새 컨텍스트를 생성하여 오버헤드 최소화

## 관련 파일 목록

### 1. WebSocket 및 인증 계층

#### `transcription/routing.py`

- **역할**: WebSocket URL 라우팅 정의
- **주요 내용**: `ws/realtime-stt/` 경로에 `RealtimeSTTConsumer` 연결
- **학습 포인트**: Django Channels의 URL 라우팅 방식

#### `transcription/middleware/websocket_jwt_auth.py`

- **역할**: WebSocket 연결 시 JWT 쿠키 기반 인증 처리
- **주요 내용**:
  - `JWTWebSocketAuthMiddleware`: JWT 토큰 검증 및 사용자 인증
  - `JWTAuthMiddlewareStack`: 미들웨어 스택 구성
- **학습 포인트**: 비동기 환경에서의 인증 처리, 토큰 갱신 로직

#### `transcription/consumers/realtime_stt_consumer.py`

- **역할**: WebSocket 연결 관리 및 메시지 처리
- **주요 내용**:
  - `RealtimeSTTConsumer`: WebSocket Consumer 메인 클래스
  - Handler 초기화 및 세션 컨텍스트 관리
- **학습 포인트**: 비동기 WebSocket 처리, Handler 패턴

#### `transcription/consumers/session_context.py`

- **역할**: 세션 상태를 담는 불변 컨텍스트 객체
- **주요 내용**:
  - `SessionContext`: 세션 처리에 필요한 모든 상태를 담는 불변 데이터 구조
  - `increment_chunk_count`: 청크 개수 증가 (새 컨텍스트 반환)
  - `increment_sequence_number`: 시퀀스 번호 증가 (새 컨텍스트 반환)
  - `update_metadata`: 메타데이터 업데이트 (새 컨텍스트 반환)
- **학습 포인트**: Context Object Pattern, 불변성(Immutability), 상태 관리

#### `transcription/consumers/realtime_stt_message_handler.py`

- **역할**: WebSocket 메시지 처리 Handler
- **주요 내용**:
  - `MessageHandler`: WebSocket 메시지 처리 (start, end, audio)
  - `handle_start`: 세션 시작 및 SessionContext 생성
  - `handle_audio`: 오디오 청크 처리 및 SessionContext 업데이트
  - `handle_end`: 세션 종료 처리
  - `close_queue`: 오디오 큐 종료 신호 전송
- **학습 포인트**: Handler 패턴, SessionContext 생성 및 업데이트

#### `transcription/consumers/realtime_stt_response_handler.py`

- **역할**: WebSocket 응답 전송 Handler
- **주요 내용**:
  - `ResponseHandler`: 응답 전송 로직
  - `send_ack`: 확인 메시지 전송
  - `send_error`: 에러 메시지 전송
- **학습 포인트**: 응답 전송 추상화

#### `transcription/consumers/realtime_stt_stt_handler.py`

- **역할**: STT 스트림 처리 Handler
- **주요 내용**:
  - `STTHandler`: STT 스트림 처리 및 결과 전송
  - `process_stream`: STT 스트림 처리 메인 로직
- **학습 포인트**: STT 스트림 처리, 에러 처리

#### `transcription/consumers/realtime_stt_audio_handler.py`

- **역할**: 오디오 청크 생성 Handler
- **주요 내용**:
  - `AudioHandler`: 오디오 청크 제너레이터
  - `generate_chunks`: 큐에서 오디오 청크를 비동기적으로 생성
- **학습 포인트**: 비동기 제너레이터, Queue 종료 신호 처리

#### `transcription/consumers/realtime_stt_helpers.py`

- **역할**: Consumer 헬퍼 함수
- **주요 내용**:
  - `extract_session_id`: 세션 ID 추출 및 검증
  - `extract_input_format`: MIME 타입에서 입력 형식 추출
- **학습 포인트**: 유틸리티 함수 분리

### 4. 오디오 변환 계층

#### `modules/realtime_stt/daglo/audio_adapter.py`

- **역할**: 오디오 형식 변환
- **주요 내용**:
  - `convert_to_linear16`: 단일 오디오를 LINEAR16 PCM으로 변환
  - `StreamingAudioConverter`: 스트리밍 오디오 변환기
    - `write_chunk`: WebM 청크를 stdin에 전송

- **학습 포인트**: ffmpeg를 이용한 오디오 변환, 스트리밍 처리, 비동기 subprocess
