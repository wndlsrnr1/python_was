## 오디오 형식 이해

### 오디오 형식의 구성 요소

오디오 파일은 다음 요소로 구성됩니다:

1. **컨테이너 형식**: 파일 포맷 (WebM, MP4, WAV 등)
2. **오디오 코덱**: 압축 알고리즘 (Opus, AAC, PCM 등)
3. **샘플레이트**: 초당 샘플 수 (Hz)
4. **비트 깊이**: 샘플당 비트 수
5. **채널 수**: 모노(1), 스테레오(2) 등

### WebM 형식

WebM은 웹에서 사용하기 위해 개발된 오픈 소스 컨테이너 형식입니다:

- **코덱**: Opus, Vorbis
- **특징**:
  - 높은 압축률
  - 스트리밍에 적합
  - 브라우저에서 네이티브 지원
- **용도**: 웹 브라우저에서 녹음된 오디오

### LINEAR16 PCM 형식

LINEAR16 PCM은 압축되지 않은 원시 오디오 데이터입니다:

- **특징**:
  - 압축 없음 (원본 품질 유지)
  - 처리 속도 빠름
  - 파일 크기 큼
- **용도**: STT 서버가 요구하는 표준 형식

### 형식 변환의 필요성

STT 서버는 특정 형식의 오디오를 요구합니다:

- **Daglo STT 서버 요구사항**:
  - 형식: LINEAR16 PCM
  - 샘플레이트: 16000Hz
  - 채널: 모노 (1 채널)
  - 비트 깊이: 16비트

웹 브라우저에서 녹음된 WebM 오디오를 STT 서버가 요구하는 LINEAR16 PCM으로 변환해야 합니다.

## 스트리밍 변환 원리

### 배치 변환 vs 스트리밍 변환

**배치 변환:**

- 전체 파일을 메모리에 로드
- 변환 후 결과 반환
- 메모리 사용량 큼
- 실시간 처리에 부적합

**스트리밍 변환:**

- 청크 단위로 처리
- 메모리 사용량 적음
- 실시간 처리 가능
- 지연 시간 최소화

### ffmpeg를 이용한 변환

ffmpeg는 명령줄 기반 오디오/비디오 변환 도구입니다:

```bash
ffmpeg -i input.webm -f s16le -ar 16000 -ac 1 -acodec pcm_s16le output.raw
```

**옵션 설명:**

- `-i input.webm`: 입력 파일
- `-f s16le`: 출력 형식 (signed 16-bit little-endian)
- `-ar 16000`: 샘플레이트 16kHz
- `-ac 1`: 모노 채널
- `-acodec pcm_s16le`: PCM 코덱
- `output.raw`: 출력 파일

### 파이프를 이용한 스트리밍

stdin/stdout 파이프를 이용하면 파일 없이 스트리밍 변환이 가능합니다:

```bash
ffmpeg -i pipe:0 -f s16le -ar 16000 -ac 1 -acodec pcm_s16le pipe:1
```

- `pipe:0`: stdin에서 입력 읽기
- `pipe:1`: stdout으로 출력 쓰기

### 클래스 구조

class StreamingAudioConverter:

### 프로세스 시작

비동기 컨텍스트 매니저를 이용하여 프로세스를 시작합니다:

```python
async def __aenter__(self):
    """ffmpeg 프로세스 시작"""
    # ffmpeg 명령어 구성
    cmd = [
        "ffmpeg",
        "-i", "pipe:0",  # stdin에서 입력
        "-f", "s16le",  # 출력 형식
        "-ar", "16000",  # 샘플레이트 16kHz
        "-ac", "1",  # 모노 채널
        "-acodec", "pcm_s16le",  # PCM 코덱
        "-loglevel", "error",  # 에러만 로깅
        "pipe:1",  # stdout으로 출력
    ]

    # 비동기 subprocess 생성
    self.process = await asyncio.create_subprocess_exec(
        *cmd,
        stdin=asyncio.subprocess.PIPE,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )

    return self
```

### 청크 전송

WebM 청크를 stdin에 전송합니다:

```python
async def write_chunk(self, chunk: bytes):
    """WebM 청크를 stdin에 전송"""
    if self.process is None or self.process.stdin is None:
        raise RuntimeError("프로세스가 시작되지 않았습니다")

    if self._closed:
        raise RuntimeError("프로세스가 이미 종료되었습니다")

    try:
        self.process.stdin.write(chunk)
        await self.process.stdin.drain()  # 버퍼 플러시
    except Exception as e:
        logger.error(f"청크 전송 실패: {str(e)}")
        raise
```

### PCM 청크 읽기

stdout에서 변환된 PCM 청크를 읽습니다:

```python
async def read_pcm_chunk(self, chunk_size: int = 8192) -> bytes:
    """stdout에서 PCM 청크를 읽습니다"""
    if self.process is None or self.process.stdout is None:
        raise RuntimeError("프로세스가 시작되지 않았습니다")

    if self._closed:
        return b""

    try:
        chunk = await self.process.stdout.read(chunk_size)
        return chunk
    except Exception as e:
        logger.error(f"PCM 청크 읽기 실패: {str(e)}")
        raise
```

### 프로세스 종료

리소스를 정리하고 프로세스를 종료합니다:

```python
async def close(self):
    """프로세스 종료 및 정리"""
    if self._closed:
        return

    self._closed = True

    if self.process is None:
        return

    # stdin 닫기
    if self.process.stdin and not self.process.stdin.is_closing():
        self.process.stdin.close()
        await self.process.stdin.wait_closed()

    # 프로세스 종료 대기
    try:
        await asyncio.wait_for(self.process.wait(), timeout=5.0)
    except asyncio.TimeoutError:
        # 타임아웃 시 강제 종료
        self.process.kill()
        await self.process.wait()
```

### 컨텍스트 매니저와 자동 정리

`async with` 구문을 사용할 때 자동으로 정리되도록 `__aexit__` 메서드를 추가해야 합니다:

```python
async def __aexit__(self, exc_type, exc_val, exc_tb):
    """컨텍스트 매니저 종료 시 자동 정리"""
    await self.close()
```

**왜 필요한가?**

- `__aenter__`만 있으면 `async with` 사용 시 자동 정리가 보장되지 않음
- `__aexit__`가 있어야 예외 발생 시에도 자동으로 `close()` 호출됨
- 리소스 누수 방지

**사용 예시:**

```python
# 자동 정리 보장
async with StreamingAudioConverter() as converter:
    await converter.write_chunk(chunk)
    pcm_chunk = await converter.read_pcm_chunk()
# 여기서 자동으로 close() 호출됨
```

## 스트림 변환 함수

### convert_stream_to_linear16

이 함수는 오디오 스트림을 LINEAR16 PCM으로 변환합니다:

```python
async def convert_stream_to_linear16(
    audio_chunks: AsyncIterator[bytes],
    input_format: str = "webm",
) -> AsyncIterator[bytes]:
    """오디오 스트림을 LINEAR16 PCM 형식으로 변환"""

    converter = StreamingAudioConverter(input_format=input_format)

    async with converter:
        # 백그라운드 태스크: WebM 청크를 stdin에 전송
        async def write_chunks():
            try:
                async for chunk in audio_chunks:
                    if chunk and len(chunk) > 0:
                        await converter.write_chunk(chunk)
            finally:
                await converter.flush()

        # 백그라운드 태스크 시작
        write_task = asyncio.create_task(write_chunks())

        # stdout에서 PCM 청크 읽기
        try:
            while True:
                pcm_chunk = await converter.read_pcm_chunk()
                if not pcm_chunk:
                    break
                yield pcm_chunk
        finally:
            # write_task 완료 대기
            await write_task
```

### 동작 원리

1. **프로세스 시작**: ffmpeg 프로세스 생성
2. **병렬 처리**:
   - 백그라운드 태스크가 WebM 청크를 stdin에 전송
   - 메인 루프가 stdout에서 PCM 청크를 읽어 yield
3. **종료 처리**: 모든 청크 전송 후 프로세스 종료

## Private.convert_audio_chunks

서비스 레이어에서 사용하는 변환 함수입니다:

@staticmethod
async def convert_audio_chunks(

## 실습: 오디오 변환 구현

### 1. 간단한 오디오 변환기 구현

```python
# simple_audio_converter.py
import asyncio
import subprocess

class SimpleAudioConverter:
    def __init__(self):
        self.process = None

    async def start(self):
        """ffmpeg 프로세스 시작"""
        cmd = [
            "ffmpeg",
            "-i", "pipe:0",
            "-f", "s16le",
            "-ar", "16000",
            "-ac", "1",
            "-acodec", "pcm_s16le",
            "-loglevel", "error",
            "pipe:1",
        ]

        self.process = await asyncio.create_subprocess_exec(
            *cmd,
            stdin=asyncio.subprocess.PIPE,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )

    async def convert_chunk(self, webm_chunk: bytes) -> bytes:
        """WebM 청크를 PCM으로 변환"""
        if self.process is None:
            await self.start()

        # stdin에 WebM 청크 전송
        self.process.stdin.write(webm_chunk)
        await self.process.stdin.drain()

        # stdout에서 PCM 청크 읽기
        pcm_chunk = await self.process.stdout.read(8192)
        return pcm_chunk

    async def close(self):
        """프로세스 종료"""
        if self.process and self.process.stdin:
            self.process.stdin.close()
            await self.process.stdin.wait_closed()

        if self.process:
            await self.process.wait()
```

### 3. 완전한 스트리밍 변환기

```python
# complete_streaming_converter.py
import asyncio
from collections.abc import AsyncIterator

async def convert_stream(
    audio_chunks: AsyncIterator[bytes],
    input_format: str = "webm",
) -> AsyncIterator[bytes]:
    """완전한 스트리밍 변환기"""

    converter = SimpleAudioConverter()

    try:
        await converter.start()

        # 백그라운드 태스크: WebM 청크 전송
        async def write_chunks():
            try:
                async for chunk in audio_chunks:
                    if chunk:
                        converter.process.stdin.write(chunk)
                        await converter.process.stdin.drain()
            finally:
                converter.process.stdin.close()
                await converter.process.stdin.wait_closed()

        write_task = asyncio.create_task(write_chunks())

        # 메인 루프: PCM 청크 읽기
        try:
            while True:
                pcm_chunk = await converter.process.stdout.read(8192)
                if not pcm_chunk:
                    break
                yield pcm_chunk
        finally:
            await write_task

    finally:
        await converter.close()

# 사용 예시
async def main():
    async def webm_source():
        for i in range(10):
            yield b"webm_chunk_" + str(i).encode()

    async for pcm_chunk in convert_stream(webm_source()):
        print(f"PCM 청크: {len(pcm_chunk)} bytes")

asyncio.run(main())
```

### gRPC 재연결 시나리오

gRPC 연결이 끊기고 재시도할 때 발생할 수 있는 문제와 해결 방안입니다.

#### 문제 상황

현재 구조: `WebSocket → Queue → AudioHandler → ffmpeg (stdin/stdout) → gRPC 스트림 → STT 서버`

gRPC 연결이 끊기고 재시도할 때:

1. **ffmpeg 프로세스**: 계속 실행 중 (stdin/stdout 유지)
2. **gRPC 연결**: 새로운 연결 생성 (새로운 스트림)
3. **Queue**: 기존 Queue는 종료 신호를 받아 재사용 불가능
4. **문제**: 기존 ffmpeg의 stdout과 새로운 gRPC 스트림이 매칭되지 않음

#### 핵심 이슈

- **리소스 불일치**: ffmpeg 프로세스는 유지되지만 gRPC는 새로 생성
- **Queue 재사용 불가능**: 종료된 Queue는 재사용할 수 없음
- **상태 동기화 실패**: 재연결 시 기존 stdin/stdout 상태를 인지하지 못함
- **파이프 고정**: ffmpeg 프로세스가 한 번 시작되면 그 프로세스의 stdout은 고정됨

#### 해결 방안

gRPC 재연결 시 다음을 수행해야 합니다:

1. **기존 Queue 종료**: 종료 신호 전송
2. **새 Queue 생성**: 재시작을 위한 새 Queue 생성
3. **SessionContext에서 정보 추출**: 재시작에 필요한 정보를 SessionContext에서 가져옴
4. **ffmpeg 프로세스 재시작**: 새로운 stdout 파이프 생성 (SessionContext의 input_format 사용)
5. **새 STT 태스크 시작**: 새 Queue와 새 ffmpeg 프로세스로 시작

```python
# 재시작 시나리오
async def restart_stt_processing(self):
    """STT 처리 재시작"""
    if not self.session_context:
        return  # SessionContext가 없으면 재시작 불가
    
    # 1. 기존 STT 태스크 종료
    if self.stt_processing_task:
        self.stt_processing_task.cancel()
        try:
            await self.stt_processing_task
        except asyncio.CancelledError:
            pass
    
    # 2. 기존 Queue 종료 (None 전송)
    await self.message_handler.close_queue()
    
    # 3. 새 Queue 생성 (재사용 불가능하므로 새로 생성)
    self.message_handler.audio_queue = asyncio.Queue()
    
    # 4. SessionContext에서 정보 추출
    session_id = self.session_context.session_id
    language_code = self.session_context.language_code
    interim_results = self.session_context.interim_results
    input_format = self.session_context.input_format  # ffmpeg 재시작에 필요
    
    # 5. 새 STT 태스크 시작 (SessionContext 정보 사용)
    self.stt_processing_task = asyncio.create_task(
        self.stt_handler.process_stream(
            self.message_handler.audio_queue,  # 새 Queue
            session_id,  # SessionContext에서
            language_code,  # SessionContext에서
            interim_results,  # SessionContext에서
            input_format,  # SessionContext에서 (ffmpeg 재시작에 필요)
            send_func,
            send_error_func,
            lambda: self.session_context.sequence_number,  # SessionContext에서
        )
    )
```

### SessionContext에서 정보 추출

ffmpeg 재시작 시 필요한 정보는 모두 SessionContext에 저장되어 있습니다:

```python
# SessionContext 구조
@dataclass
class SessionContext:
    session_id: UUID
    session: Session
    base_path: str
    input_format: str  # ← ffmpeg 재시작에 필요
    language_code: str  # ← STT 설정에 필요
    interim_results: bool  # ← STT 설정에 필요
    metadata: dict[str, Any]
    start_time: datetime
    config: dict[str, Any]
    chunk_count: int
    sequence_number: int
```

**재시작 시 필요한 정보:**

- **input_format**: ffmpeg 프로세스 재시작 시 입력 형식 지정
- **language_code**: STT 스트림 설정
- **interim_results**: STT 스트림 설정
- **session_id**: STT 스트림 식별

**정보 추출 예제:**

```python
# SessionContext에서 정보 추출
if self.session_context:
    # ffmpeg 재시작에 필요한 정보
    input_format = self.session_context.input_format  # "webm", "mp4" 등
    
    # STT 스트림 설정에 필요한 정보
    language_code = self.session_context.language_code  # "ko-KR" 등
    interim_results = self.session_context.interim_results  # True/False
    
    # STT 스트림 식별에 필요한 정보
    session_id = self.session_context.session_id
```

이 패턴의 장점:
- **정보 보존**: 재시작 시에도 모든 설정 정보가 SessionContext에 보존됨
- **일관성**: 재시작 전후의 설정이 동일하게 유지됨
- **명확성**: 필요한 정보가 SessionContext에 명시적으로 저장됨

**핵심 개념:**

```
1. gRPC 연결 끊김
   ↓
2. 기존 Queue 종료 (put(None))
   ↓
3. 제너레이터 종료
   ↓
4. SessionContext에서 정보 추출
   │   ├─→ input_format (ffmpeg 재시작에 필요)
   │   ├─→ language_code (STT 설정)
   │   ├─→ interim_results (STT 설정)
   │   └─→ session_id (STT 식별)
   ↓
5. 새 Queue 생성 (asyncio.Queue())
   ↓
6. ffmpeg 프로세스 재시작
   │   └─→ input_format 사용하여 새 프로세스 시작
   ↓
7. 새 STT 태스크 시작
   │   ├─→ 새 Queue 사용
   │   ├─→ SessionContext 정보 사용
   │   └─→ 새 ffmpeg 프로세스 사용
   ↓
8. 정상 동작 재개 ✅
```

**주의사항:**

- **Queue 재사용 불가능**: 종료된 Queue는 재사용할 수 없으므로 반드시 새로 생성
- **ffmpeg 재시작 필요**: 새로운 stdout 파이프를 위해 프로세스 재시작 필요
- **SessionContext 정보 활용**: 재시작 시 필요한 모든 정보를 SessionContext에서 추출
- **SessionContext 유지**: 재시작 시에도 SessionContext는 유지하여 상태 보존

## 부록: subprocess 파이프와 비동기 컨텍스트 매니저

### stdin/stdout/stderr 파이프 설정

`asyncio.create_subprocess_exec`에서 파이프를 설정할 때 사용하는 옵션들입니다:

```python
self.process = await asyncio.create_subprocess_exec(
    *cmd,
    stdin=asyncio.subprocess.PIPE,   # 표준 입력 파이프
    stdout=asyncio.subprocess.PIPE,  # 표준 출력 파이프
    stderr=asyncio.subprocess.PIPE,  # 표준 에러 파이프
)
```

**각 파이프의 역할:**

- **stdin (PIPE)**: 프로세스에 데이터를 전송하는 입력 스트림

  - `process.stdin.write(data)`: 데이터 전송
  - `await process.stdin.drain()`: 버퍼 플러시
  - `process.stdin.close()`: 입력 종료

- **stdout (PIPE)**: 프로세스로부터 데이터를 받는 출력 스트림

  - `await process.stdout.read(size)`: 데이터 읽기
  - 프로세스가 종료되면 자동으로 닫힘

- **stderr (PIPE)**: 프로세스의 에러 메시지를 받는 스트림
  - `await process.stderr.read()`: 에러 메시지 읽기
  - 디버깅 및 에러 처리에 사용

**핵심 개념:**

- `PIPE`를 지정하면 Python이 프로세스와 통신할 수 있는 파이프를 생성
- 파이프는 프로세스별로 독립적이며, 프로세스가 종료되면 함께 닫힘
- ffmpeg의 경우 `pipe:0`(stdin), `pipe:1`(stdout)을 사용하여 스트리밍 변환 수행

### **aenter** 메서드

`__aenter__`는 비동기 컨텍스트 매니저의 진입점입니다:

```python
async def __aenter__(self):
    """ffmpeg 프로세스 시작"""
    # 프로세스 생성 및 초기화
    self.process = await asyncio.create_subprocess_exec(...)
    return self
```

**동작 원리:**

1. `async with` 구문 진입 시 `__aenter__` 자동 호출
2. 프로세스 생성 및 초기화 수행
3. `return self`로 컨텍스트 매니저 객체 반환
4. `async with` 블록 내에서 객체 사용
5. 블록 종료 시 `__aexit__` 자동 호출 (정리 작업)

**사용 예시:**

```python
# 자동으로 __aenter__ 호출 → 프로세스 시작
async with StreamingAudioConverter() as converter:
    await converter.write_chunk(chunk)
    pcm_chunk = await converter.read_pcm_chunk()
# 자동으로 __aexit__ 호출 → 프로세스 정리
```

**장점:**

- 리소스 관리 자동화: 예외 발생 시에도 자동 정리
- 코드 간결성: 명시적인 `close()` 호출 불필요
- 안전성: 리소스 누수 방지

### subprocess API 상세 설명

#### process.stdin (StreamWriter) API

`process.stdin`은 프로세스에 데이터를 전송하는 비동기 스트림 라이터입니다:

```python
# 데이터 전송
process.stdin.write(data)  # bytes 데이터 전송 (비동기 아님, 버퍼에 씀)
await process.stdin.drain()  # 버퍼가 비워질 때까지 대기

# 스트림 상태 확인
if process.stdin.is_closing():  # 닫히는 중인지 확인
    # 이미 닫히는 중

# 스트림 닫기
process.stdin.close()  # 더 이상 데이터 전송 불가
await process.stdin.wait_closed()  # 완전히 닫힐 때까지 대기
```

**주요 메서드:**

- `write(data: bytes)`: 데이터를 버퍼에 씀 (비동기 아님, 즉시 반환)
- `drain()`: 버퍼가 비워질 때까지 대기 (실제 전송 보장)
- `close()`: 스트림 닫기 시작
- `wait_closed()`: 스트림이 완전히 닫힐 때까지 대기
- `is_closing()`: 닫히는 중인지 확인

**사용 패턴:**

```python
# 올바른 사용법
await process.stdin.write(chunk)  # 버퍼에 쓰기
await process.stdin.drain()  # 전송 완료 대기

# 종료 시
process.stdin.close()  # 더 이상 쓰지 않음을 알림
await process.stdin.wait_closed()  # 완전히 닫힐 때까지 대기
```

#### process.stdout (StreamReader) API

`process.stdout`은 프로세스로부터 데이터를 받는 비동기 스트림 리더입니다:

```python
# 데이터 읽기
chunk = await process.stdout.read(8192)  # 최대 8192 bytes 읽기
line = await process.stdout.readline()  # 한 줄 읽기 (줄바꿈까지)

# 스트림 상태 확인
if process.stdout.at_eof():  # 더 이상 읽을 데이터가 없음
    break
```

**주요 메서드:**

- `read(n: int)`: 최대 n bytes 읽기 (비동기)
- `readline()`: 한 줄 읽기 (줄바꿈 문자 포함, 비동기)
- `readuntil(separator)`: 구분자까지 읽기 (비동기)
- `at_eof()`: 더 이상 읽을 데이터가 없는지 확인

**사용 패턴:**

```python
# 청크 단위 읽기
while True:
    chunk = await process.stdout.read(8192)
    if not chunk:  # 빈 bytes는 EOF 의미
        break
    # chunk 처리

# 또는 at_eof() 사용
while not process.stdout.at_eof():
    chunk = await process.stdout.read(8192)
    # chunk 처리
```

#### process (Process) API

`process`는 생성된 서브프로세스를 나타내는 객체입니다:

```python
# 프로세스 상태 확인
pid = process.pid  # 프로세스 ID
returncode = process.returncode  # 종료 코드 (None이면 실행 중)

# 프로세스 종료 대기
returncode = await process.wait()  # 프로세스 종료까지 대기

# 프로세스 종료
process.terminate()  # 정상 종료 신호 전송 (SIGTERM)
process.kill()  # 강제 종료 (SIGKILL)
```

**주요 속성/메서드:**

- `pid`: 프로세스 ID (int)
- `returncode`: 종료 코드 (None = 실행 중, 0 = 성공, 기타 = 에러)
- `wait()`: 프로세스 종료까지 대기 (비동기)
- `terminate()`: 정상 종료 신호 전송
- `kill()`: 강제 종료 신호 전송

**사용 패턴:**

```python
# 프로세스 상태 확인
if process.returncode is None:
    # 아직 실행 중
    pass
elif process.returncode == 0:
    # 정상 종료
    pass
else:
    # 에러로 종료
    pass

# 종료 대기
try:
    await asyncio.wait_for(process.wait(), timeout=5.0)
except asyncio.TimeoutError:
    process.kill()  # 타임아웃 시 강제 종료
    await process.wait()
```

### subprocess 생명주기

subprocess의 전체 생명주기는 다음과 같습니다:

```
1. 프로세스 생성
   ↓
   process = await asyncio.create_subprocess_exec(...)
   ↓
2. stdin에 데이터 쓰기 (반복)
   ↓
   await process.stdin.write(chunk)
   await process.stdin.drain()
   ↓
3. stdout에서 데이터 읽기 (반복)
   ↓
   chunk = await process.stdout.read(size)
   ↓
4. stdin 닫기
   ↓
   process.stdin.close()
   await process.stdin.wait_closed()
   ↓
5. 프로세스 종료 대기
   ↓
   await process.wait()
   ↓
6. 프로세스 정리 완료
```

**단계별 상세 설명:**

1. **프로세스 생성**: `create_subprocess_exec`로 프로세스와 파이프 생성
2. **데이터 쓰기**: `stdin.write()`로 데이터 전송, `drain()`으로 전송 완료 보장
3. **데이터 읽기**: `stdout.read()`로 프로세스 출력 읽기
4. **stdin 닫기**: 더 이상 데이터가 없음을 프로세스에 알림
5. **종료 대기**: 프로세스가 정상 종료될 때까지 대기
6. **정리 완료**: 모든 리소스 해제

**전체 코드 예시:**

```python
async def process_audio_stream():
    # 1. 프로세스 생성
    process = await asyncio.create_subprocess_exec(
        "ffmpeg", "-i", "pipe:0", "pipe:1",
        stdin=asyncio.subprocess.PIPE,
        stdout=asyncio.subprocess.PIPE,
    )

    try:
        # 2. stdin에 데이터 쓰기
        async def write_data():
            async for chunk in audio_chunks:
                await process.stdin.write(chunk)
                await process.stdin.drain()
            # 4. stdin 닫기
            process.stdin.close()
            await process.stdin.wait_closed()

        write_task = asyncio.create_task(write_data())

        # 3. stdout에서 데이터 읽기
        while not process.stdout.at_eof():
            chunk = await process.stdout.read(8192)
            if chunk:
                yield chunk

        await write_task

        # 5. 프로세스 종료 대기
        await process.wait()

    finally:
        # 6. 정리 (필요 시)
        if process.returncode is None:
            process.kill()
            await process.wait()
```
