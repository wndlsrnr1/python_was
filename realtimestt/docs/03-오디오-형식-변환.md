## 오디오 형식 이해

### 오디오 형식의 구성 요소

오디오 파일은 다음 요소로 구성됩니다:

1. **컨테이너 형식**: 파일 포맷 (WebM, MP4, WAV 등)
2. **오디오 코덱**: 압축 알고리즘 (Opus, AAC, PCM 등)
3. **샘플레이트**: 초당 샘플 수 (Hz)
4. **비트 깊이**: 샘플당 비트 수
5. **채널 수**: 모노(1), 스테레오(2) 등

### WebM 형식

WebM은 웹에서 사용하기 위해 개발된 오픈 소스 컨테이너 형식입니다:

- **코덱**: Opus, Vorbis
- **특징**:
  - 높은 압축률
  - 스트리밍에 적합
  - 브라우저에서 네이티브 지원
- **용도**: 웹 브라우저에서 녹음된 오디오

### LINEAR16 PCM 형식

LINEAR16 PCM은 압축되지 않은 원시 오디오 데이터입니다:

- **특징**:
  - 압축 없음 (원본 품질 유지)
  - 처리 속도 빠름
  - 파일 크기 큼
- **용도**: STT 서버가 요구하는 표준 형식

### 형식 변환의 필요성

STT 서버는 특정 형식의 오디오를 요구합니다:

- **Daglo STT 서버 요구사항**:
  - 형식: LINEAR16 PCM
  - 샘플레이트: 16000Hz
  - 채널: 모노 (1 채널)
  - 비트 깊이: 16비트

웹 브라우저에서 녹음된 WebM 오디오를 STT 서버가 요구하는 LINEAR16 PCM으로 변환해야 합니다.

## 스트리밍 변환 원리

### 배치 변환 vs 스트리밍 변환

**배치 변환:**

- 전체 파일을 메모리에 로드
- 변환 후 결과 반환
- 메모리 사용량 큼
- 실시간 처리에 부적합

**스트리밍 변환:**

- 청크 단위로 처리
- 메모리 사용량 적음
- 실시간 처리 가능
- 지연 시간 최소화

### ffmpeg를 이용한 변환

ffmpeg는 명령줄 기반 오디오/비디오 변환 도구입니다:

```bash
ffmpeg -i input.webm -f s16le -ar 16000 -ac 1 -acodec pcm_s16le output.raw
```

**옵션 설명:**

- `-i input.webm`: 입력 파일
- `-f s16le`: 출력 형식 (signed 16-bit little-endian)
- `-ar 16000`: 샘플레이트 16kHz
- `-ac 1`: 모노 채널
- `-acodec pcm_s16le`: PCM 코덱
- `output.raw`: 출력 파일

### 파이프를 이용한 스트리밍

stdin/stdout 파이프를 이용하면 파일 없이 스트리밍 변환이 가능합니다:

```bash
ffmpeg -i pipe:0 -f s16le -ar 16000 -ac 1 -acodec pcm_s16le pipe:1
```

- `pipe:0`: stdin에서 입력 읽기
- `pipe:1`: stdout으로 출력 쓰기

## StreamingAudioConverter 구현

### 클래스 구조

`StreamingAudioConverter`는 ffmpeg 프로세스를 관리하고 스트리밍 변환을 수행합니다:

```python
class StreamingAudioConverter:
    def __init__(self, input_format: str = "webm"):
        self.input_format = input_format
        self.process = None
        self._closed = False
```

### 프로세스 시작

비동기 컨텍스트 매니저를 이용하여 프로세스를 시작합니다:

```python
async def __aenter__(self):
    """ffmpeg 프로세스 시작"""
    # ffmpeg 명령어 구성
    cmd = [
        "ffmpeg",
        "-i", "pipe:0",  # stdin에서 입력
        "-f", "s16le",  # 출력 형식
        "-ar", "16000",  # 샘플레이트 16kHz
        "-ac", "1",  # 모노 채널
        "-acodec", "pcm_s16le",  # PCM 코덱
        "-loglevel", "error",  # 에러만 로깅
        "pipe:1",  # stdout으로 출력
    ]

    # 비동기 subprocess 생성
    self.process = await asyncio.create_subprocess_exec(
        *cmd,
        stdin=asyncio.subprocess.PIPE,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )

    return self
```

### 청크 전송

WebM 청크를 stdin에 전송합니다:

```python
async def write_chunk(self, chunk: bytes):
    """WebM 청크를 stdin에 전송"""
    if self.process is None or self.process.stdin is None:
        raise RuntimeError("프로세스가 시작되지 않았습니다")

    if self._closed:
        raise RuntimeError("프로세스가 이미 종료되었습니다")

    try:
        self.process.stdin.write(chunk)
        await self.process.stdin.drain()  # 버퍼 플러시
    except Exception as e:
        logger.error(f"청크 전송 실패: {str(e)}")
        raise
```

### PCM 청크 읽기

stdout에서 변환된 PCM 청크를 읽습니다:

```python
async def read_pcm_chunk(self, chunk_size: int = 8192) -> bytes:
    """stdout에서 PCM 청크를 읽습니다"""
    if self.process is None or self.process.stdout is None:
        raise RuntimeError("프로세스가 시작되지 않았습니다")

    if self._closed:
        return b""

    try:
        chunk = await self.process.stdout.read(chunk_size)
        return chunk
    except Exception as e:
        logger.error(f"PCM 청크 읽기 실패: {str(e)}")
        raise
```

### 프로세스 종료

리소스를 정리하고 프로세스를 종료합니다:

```python
async def close(self):
    """프로세스 종료 및 정리"""
    if self._closed:
        return

    self._closed = True

    if self.process is None:
        return

    # stdin 닫기
    if self.process.stdin and not self.process.stdin.is_closing():
        self.process.stdin.close()
        await self.process.stdin.wait_closed()

    # 프로세스 종료 대기
    try:
        await asyncio.wait_for(self.process.wait(), timeout=5.0)
    except asyncio.TimeoutError:
        # 타임아웃 시 강제 종료
        self.process.kill()
        await self.process.wait()
```

### 컨텍스트 매니저와 자동 정리

`async with` 구문을 사용할 때 자동으로 정리되도록 `__aexit__` 메서드를 추가해야 합니다:

```python
async def __aexit__(self, exc_type, exc_val, exc_tb):
    """컨텍스트 매니저 종료 시 자동 정리"""
    await self.close()
```

**왜 필요한가?**

- `__aenter__`만 있으면 `async with` 사용 시 자동 정리가 보장되지 않음
- `__aexit__`가 있어야 예외 발생 시에도 자동으로 `close()` 호출됨
- 리소스 누수 방지

**사용 예시:**

```python
# 자동 정리 보장
async with StreamingAudioConverter() as converter:
    await converter.write_chunk(chunk)
    pcm_chunk = await converter.read_pcm_chunk()
# 여기서 자동으로 close() 호출됨
```

## 스트림 변환 함수

### convert_stream_to_linear16

이 함수는 오디오 스트림을 LINEAR16 PCM으로 변환합니다:

```python
async def convert_stream_to_linear16(
    audio_chunks: AsyncIterator[bytes],
    input_format: str = "webm",
) -> AsyncIterator[bytes]:
    """오디오 스트림을 LINEAR16 PCM 형식으로 변환"""

    converter = StreamingAudioConverter(input_format=input_format)

    async with converter:
        # 백그라운드 태스크: WebM 청크를 stdin에 전송
        async def write_chunks():
            try:
                async for chunk in audio_chunks:
                    if chunk and len(chunk) > 0:
                        await converter.write_chunk(chunk)
            finally:
                await converter.flush()

        # 백그라운드 태스크 시작
        write_task = asyncio.create_task(write_chunks())

        # stdout에서 PCM 청크 읽기
        try:
            while True:
                pcm_chunk = await converter.read_pcm_chunk()
                if not pcm_chunk:
                    break
                yield pcm_chunk
        finally:
            # write_task 완료 대기
            await write_task
```

### 동작 원리

1. **프로세스 시작**: ffmpeg 프로세스 생성
2. **병렬 처리**:
   - 백그라운드 태스크가 WebM 청크를 stdin에 전송
   - 메인 루프가 stdout에서 PCM 청크를 읽어 yield
3. **종료 처리**: 모든 청크 전송 후 프로세스 종료

## Private.convert_audio_chunks

서비스 레이어에서 사용하는 변환 함수입니다:

```python
@staticmethod
async def convert_audio_chunks(
    audio_chunks: AsyncIterator[bytes],
    input_format: str,
) -> AsyncIterator[bytes]:
    """오디오 청크를 LINEAR16 PCM으로 변환하는 제너레이터"""

    logger.debug(f"스트리밍 오디오 변환 시작: input_format={input_format}")

    try:
        async for pcm_chunk in convert_stream_to_linear16(
            audio_chunks,
            input_format=input_format,
        ):
            if pcm_chunk and len(pcm_chunk) > 0:
                logger.debug(f"PCM 청크 생성: size={len(pcm_chunk)} bytes")
                yield pcm_chunk

        logger.debug(f"스트리밍 오디오 변환 완료: input_format={input_format}")

    except Exception as e:
        logger.error(f"스트리밍 오디오 변환 실패: {str(e)}")
        raise ServiceError(f"오디오 스트림 변환 실패: {str(e)}", status_code=500) from e
```

## 실습: 오디오 변환 구현

### 1. 간단한 오디오 변환기 구현

```python
# simple_audio_converter.py
import asyncio
import subprocess

class SimpleAudioConverter:
    def __init__(self):
        self.process = None

    async def start(self):
        """ffmpeg 프로세스 시작"""
        cmd = [
            "ffmpeg",
            "-i", "pipe:0",
            "-f", "s16le",
            "-ar", "16000",
            "-ac", "1",
            "-acodec", "pcm_s16le",
            "-loglevel", "error",
            "pipe:1",
        ]

        self.process = await asyncio.create_subprocess_exec(
            *cmd,
            stdin=asyncio.subprocess.PIPE,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )

    async def convert_chunk(self, webm_chunk: bytes) -> bytes:
        """WebM 청크를 PCM으로 변환"""
        if self.process is None:
            await self.start()

        # stdin에 WebM 청크 전송
        self.process.stdin.write(webm_chunk)
        await self.process.stdin.drain()

        # stdout에서 PCM 청크 읽기
        pcm_chunk = await self.process.stdout.read(8192)
        return pcm_chunk

    async def close(self):
        """프로세스 종료"""
        if self.process and self.process.stdin:
            self.process.stdin.close()
            await self.process.stdin.wait_closed()

        if self.process:
            await self.process.wait()
```

### 3. 완전한 스트리밍 변환기

```python
# complete_streaming_converter.py
import asyncio
from collections.abc import AsyncIterator

async def convert_stream(
    audio_chunks: AsyncIterator[bytes],
    input_format: str = "webm",
) -> AsyncIterator[bytes]:
    """완전한 스트리밍 변환기"""

    converter = SimpleAudioConverter()

    try:
        await converter.start()

        # 백그라운드 태스크: WebM 청크 전송
        async def write_chunks():
            try:
                async for chunk in audio_chunks:
                    if chunk:
                        converter.process.stdin.write(chunk)
                        await converter.process.stdin.drain()
            finally:
                converter.process.stdin.close()
                await converter.process.stdin.wait_closed()

        write_task = asyncio.create_task(write_chunks())

        # 메인 루프: PCM 청크 읽기
        try:
            while True:
                pcm_chunk = await converter.process.stdout.read(8192)
                if not pcm_chunk:
                    break
                yield pcm_chunk
        finally:
            await write_task

    finally:
        await converter.close()

# 사용 예시
async def main():
    async def webm_source():
        for i in range(10):
            yield b"webm_chunk_" + str(i).encode()

    async for pcm_chunk in convert_stream(webm_source()):
        print(f"PCM 청크: {len(pcm_chunk)} bytes")

asyncio.run(main())
```

## 성능 최적화

### 청크 크기 조정

청크 크기는 성능에 영향을 미칩니다:

- **작은 청크**: 낮은 지연 시간, 높은 오버헤드
- **큰 청크**: 높은 처리량, 높은 지연 시간
- **권장 크기**: 8192 bytes (8KB)

### 버퍼 관리

stdin/stdout 버퍼를 적절히 관리해야 합니다:

```python
# drain()을 호출하여 버퍼 플러시
await self.process.stdin.drain()

# 버퍼 크기 제한
chunk = await self.process.stdout.read(8192)  # 최대 8KB
```

### 에러 처리

프로세스 오류를 적절히 처리해야 합니다:

```python
try:
    await self.process.wait()
except Exception as e:
    # stderr 읽기
    if self.process.stderr:
        stderr_data = await self.process.stderr.read()
        logger.error(f"ffmpeg 오류: {stderr_data.decode()}")
    raise
```

### gRPC 재연결 시나리오

gRPC 연결이 끊기고 재시도할 때 발생할 수 있는 문제와 해결 방안입니다.

#### 문제 상황

현재 구조: `WebSocket → ffmpeg (stdin/stdout) → gRPC 스트림 → STT 서버`

gRPC 연결이 끊기고 재시도할 때:

1. **ffmpeg 프로세스**: 계속 실행 중 (stdin/stdout 유지)
2. **gRPC 연결**: 새로운 연결 생성 (새로운 스트림)
3. **문제**: 기존 ffmpeg의 stdout과 새로운 gRPC 스트림이 매칭되지 않음

#### 핵심 이슈

- **리소스 불일치**: ffmpeg 프로세스는 유지되지만 gRPC는 새로 생성
- **상태 동기화 실패**: 재연결 시 기존 stdin/stdout 상태를 인지하지 못함
- **파이프 고정**: ffmpeg 프로세스가 한 번 시작되면 그 프로세스의 stdout은 고정됨

#### 해결 방안

gRPC 재연결 시 ffmpeg 프로세스도 함께 재시작하여 새로운 stdout 파이프를 생성합니다:

```python
class StreamingAudioConverter:
    async def reconnect_for_grpc(self):
        """gRPC 재연결 시 ffmpeg도 재시작하여 새 스트림에 연결"""
        # 1. 기존 프로세스 종료
        await self.close()

        # 2. 새 프로세스 시작 (새로운 stdout 파이프)
        await self.__aenter__()

        # 이제 ffmpeg의 stdout은 새로운 프로세스의 stdout이고,
        # 이것을 새로운 gRPC 스트림으로 연결하면 됨
```

**핵심 개념:**

```
ffmpeg 프로세스 시작
    ↓
새로운 stdin/stdout 파이프 생성 (프로세스별로 독립적)
    ↓
ffmpeg.stdout → gRPC 스트림 A 연결
    ↓
gRPC 연결 끊김
    ↓
ffmpeg 프로세스 재시작 (새로운 stdout 파이프 생성)
    ↓
새로운 ffmpeg.stdout → 새로운 gRPC 스트림 B 연결 ✅
```

**주의사항:**

- ffmpeg 프로세스를 재시작하면 새로운 stdin/stdout 파이프가 생성됨
- 기존 프로세스의 stdout은 이전 gRPC 연결을 가리키므로 재사용 불가
- 재연결 시 반드시 ffmpeg 프로세스를 재시작해야 함
