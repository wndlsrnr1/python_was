# 오디오 스트림 수신 및 저장 문제

## 객관식 문제

### 1. SessionContext 패턴의 가장 큰 장점은 무엇인가요?

① 상태를 직접 수정할 수 있어 빠르다  
② 상태 변경이 항상 새 객체 생성으로 표현되어 상태 동기화가 보장된다  
③ 메모리 사용량이 적다  
④ 코드가 간단하다  

**정답**: ②  
**해설**: SessionContext 패턴은 불변 객체를 사용하여 상태를 변경할 때마다 새로운 객체를 생성합니다. 이를 통해 여러 곳에서 동시에 상태를 수정하는 문제를 방지하고, 상태 동기화를 보장합니다.

---

### 2. asyncio.Queue에 종료 신호를 보내는 방법은?

① `queue.put(False)`  
② `queue.put(None)`  
③ `queue.put("END")`  
④ `queue.close()`  

**정답**: ②  
**해설**: 제너레이터 종료를 보장하기 위해 `None`을 큐에 넣어 종료 신호로 사용합니다. 제너레이터는 `None`을 받으면 `break`로 종료됩니다.

---

### 3. SessionContext의 상태를 변경할 때 올바른 방법은?

① `context.chunk_count += 1`  
② `context = context.increment_chunk_count()`  
③ `context.metadata["chunks"].append(chunk_info)`  
④ `context.update_chunk_count(1)`  

**정답**: ②  
**해설**: SessionContext는 불변 객체이므로 상태를 변경할 때는 새로운 객체를 생성해야 합니다. `increment_chunk_count()` 메서드는 새로운 SessionContext 객체를 반환합니다.

---

### 4. asyncio.Queue가 한 번 종료되면 재사용할 수 없는 이유는?

① 메모리 부족  
② 종료 신호(None)를 받은 후 제너레이터가 종료되어 재사용 불가능  
③ 큐 크기 제한  
④ 스레드 안전성 문제  

**정답**: ②  
**해설**: Queue에 `None` 종료 신호를 보내면 제너레이터가 종료되고, 종료된 Queue는 다시 사용할 수 없습니다. 재시작 시 반드시 새로운 Queue를 생성해야 합니다.

---

### 5. 오디오 청크를 파일에 저장할 때 첫 청크와 이후 청크의 처리 방식은?

① 모두 새 파일로 저장  
② 모두 기존 파일에 추가  
③ 첫 청크는 새 파일, 이후 청크는 기존 파일에 추가  
④ 첫 청크는 기존 파일에 추가, 이후 청크는 새 파일로 저장  

**정답**: ③  
**해설**: 첫 청크는 새 파일로 저장하고, 이후 청크는 기존 파일을 읽어서 데이터를 합친 후 다시 저장합니다. 이를 통해 모든 청크를 하나의 파일로 통합합니다.

---

### 6. 메타데이터를 주기적으로 저장하는 이유는?

① 성능 최적화  
② 데이터 손실 방지  
③ 메모리 절약  
④ 네트워크 대역폭 절약  

**정답**: ②  
**해설**: 메타데이터는 매 10개 청크마다 저장하여 연결이 예기치 않게 종료되어도 데이터 손실을 방지합니다.

---

## 빈칸 채우기

### 7. SessionContext는 (    ) 객체이므로 상태를 변경할 때는 새로운 객체를 생성해야 합니다.

**정답**: 불변  
**해설**: SessionContext는 불변(immutable) 객체로 설계되어 있어, 상태를 변경할 때는 항상 새로운 객체를 생성합니다. 이를 통해 상태 동기화 문제를 방지합니다.

---

### 8. 오디오 청크 제너레이터에서 종료 신호로 (    )을 받으면 안전하게 종료됩니다.

**정답**: None  
**해설**: 제너레이터는 `None`을 종료 신호로 받아 `if chunk is None: break`로 명시적으로 종료 처리합니다.

---

### 9. WebSocket Consumer의 receive 메서드는 (    ) 메시지와 (    ) 메시지를 처리합니다.

**정답**: 텍스트, 바이너리  
**해설**: `receive` 메서드는 `text_data`(JSON 형식의 제어 메시지)와 `bytes_data`(오디오 청크 데이터) 두 가지 타입의 메시지를 처리합니다.

---

### 10. AudioPipeline의 (    ) 메서드는 오디오 청크를 기존 파일에 추가합니다.

**정답**: append_chunk  
**해설**: `append_chunk` 메서드는 오디오 청크를 기존 파일에 추가하는 역할을 합니다. 첫 청크는 새 파일로 저장하고, 이후 청크는 기존 파일에 추가합니다.

---

### 11. SessionContext를 생성하는 시점은 (    ) 메시지를 받았을 때입니다.

**정답**: start  
**해설**: `start` 메시지를 받으면 세션을 초기화하고 SessionContext를 생성합니다. 이때 세션 검증, 저장 경로 생성, 메타데이터 초기화 등을 수행합니다.

---

### 13. SessionContext 패턴을 사용하면 상태 변경이 항상 새 객체 생성으로 표현되어 예측 가능성이 높아진다.

**정답**: O

## 서술형 문제

### 15. SessionContext 패턴의 장점을 설명하세요.

**정답**:  
SessionContext 패턴의 장점은 다음과 같습니다:
1. **상태 동기화 보장**: 상태 변경이 항상 새 객체 생성으로 표현되어 여러 곳에서 동시에 상태를 수정하는 문제를 방지합니다.
2. **예측 가능성**: 어떤 상태 변경이 발생했는지 명확히 추적할 수 있습니다.
3. **디버깅 용이**: 각 상태 변경 시점의 컨텍스트를 보존하여 디버깅이 용이합니다.

**해설**: 불변 객체를 사용하여 상태 관리의 복잡성을 줄이고, 동시성 문제를 방지합니다.

---

### 16. Queue 재사용 불가능 문제와 해결 방법을 설명하세요.

**정답**:  
asyncio.Queue는 한 번 종료되면 재사용할 수 없습니다. Queue에 `None` 종료 신호를 보내면 제너레이터가 종료되고, 종료된 Queue는 다시 사용할 수 없습니다.

해결 방법:
1. 기존 Queue 종료: `close_queue()` 메서드를 통해 `None` 전송
2. 새 Queue 생성: `asyncio.Queue()`로 새로운 Queue 생성
3. 새 STT 태스크 시작: 새 Queue와 함께 STT 처리 태스크 재시작

**해설**: 재시작 시 기존 Queue를 재사용하면 제너레이터가 종료 신호를 받지 못하므로, 반드시 새 Queue를 생성해야 합니다.
