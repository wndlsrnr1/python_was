# WebSocket 연결 및 인증 문제

## 객관식 문제

### 1. WebSocket과 HTTP의 가장 큰 차이점은 무엇인가요?

① HTTP는 양방향 통신을 지원하지만 WebSocket은 단방향 통신만 지원한다  
② WebSocket은 한 번 연결을 수립하면 지속적으로 데이터를 주고받을 수 있지만, HTTP는 요청-응답 후 연결이 종료된다  
③ HTTP는 실시간 통신에 최적화되어 있지만 WebSocket은 배치 처리에 적합하다  
④ WebSocket은 HTTP보다 오버헤드가 크다  

**정답**: ②  
**해설**: WebSocket은 양방향 통신을 지원하며, 한 번 연결을 수립하면 지속적으로 데이터를 주고받을 수 있습니다. HTTP는 요청-응답 모델로 각 요청마다 연결이 종료됩니다.

---

### 2. WebSocket 연결 수립 시 서버가 반환하는 HTTP 상태 코드는 무엇인가요?

① 200 OK  
② 101 Switching Protocols  
③ 301 Moved Permanently  
④ 404 Not Found  

**정답**: ②  
**해설**: WebSocket 연결은 HTTP Upgrade 요청으로 시작되며, 서버가 101 Switching Protocols를 반환하면 WebSocket 프로토콜로 전환됩니다.

---

### 3. ASGI에서 scope 객체의 역할이 아닌 것은?

① 연결 정보 제공 (연결 타입, 경로, 클라이언트 정보)  
② 요청 메타데이터 저장 (HTTP 헤더, 쿠키, 쿼리 파라미터)  
③ 데이터베이스 쿼리 실행  
④ 인증 정보 저장 (인증된 사용자 정보)  

**정답**: ③  
**해설**: scope 객체는 연결에 대한 정보를 담은 딕셔너리로, 데이터베이스 쿼리 실행과는 무관합니다. 연결 정보, 메타데이터, 인증 정보를 저장하는 역할을 합니다.

---

### 4. WebSocket scope에서 쿠키를 추출할 수 있는 시점은?

① 연결 수립 후 언제든지  
② HTTP Upgrade 요청의 초기 헤더에서만  
③ disconnect 메서드에서만  
④ receive 메서드에서만  

**정답**: ②  
**해설**: WebSocket은 연결 수립 후 헤더가 없으므로, 인증에 필요한 쿠키는 HTTP Upgrade 요청의 초기 헤더에서만 추출 가능합니다.

---

### 5. JWT의 세 부분 중 서명 알고리즘 정보가 포함된 부분은?

① header  
② payload  
③ signature  
④ claim  

**정답**: ①  
**해설**: JWT의 header에는 토큰 타입(JWT)과 서명 알고리즘(예: HS256, RS256)이 포함됩니다.

---

### 6. Consumer 패턴에서 WebSocket 연결 종료 시 호출되는 메서드는?

① connect()  
② disconnect()  
③ receive()  
④ accept()  

**정답**: ②  
**해설**: Consumer 패턴에서 `disconnect()` 메서드는 WebSocket 연결이 종료될 때 호출되어 리소스 정리, 세션 종료 등을 수행합니다.

---

## 빈칸 채우기

### 7. WebSocket 연결은 HTTP (    ) 요청으로 시작됩니다.

**정답**: Upgrade  
**해설**: WebSocket 연결은 HTTP Upgrade 요청으로 시작되며, 서버가 101 Switching Protocols를 반환하면 WebSocket 프로토콜로 전환됩니다.

---

### 8. ASGI는 WSGI의 (    ) 버전으로, WebSocket과 같은 장기 연결을 지원합니다.

**정답**: 비동기  
**해설**: ASGI(Asynchronous Server Gateway Interface)는 WSGI의 비동기 버전으로, WebSocket과 같은 장기 연결을 지원합니다.

---

### 9. JWT의 두 번째 부분인 (    )에는 클레임(claim) 정보가 포함됩니다.

**정답**: payload  
**해설**: JWT는 header, payload, signature 세 부분으로 구성되며, payload에는 사용자 ID, 권한, 만료 시간 등의 클레임 정보가 포함됩니다.

---

### 10. Consumer 클래스에서 WebSocket 메시지를 받을 때 호출되는 메서드는 (    )입니다.

**정답**: receive  
**해설**: `receive()` 메서드는 클라이언트로부터 메시지를 받을 때 호출되며, 메시지 타입에 따라 적절한 처리 로직을 실행합니다.

---

### 11. WebSocket scope에서 미들웨어가 설정하는 인증된 사용자 정보는 (    ) 필드에 저장됩니다.

**정답**: user  
**해설**: 미들웨어에서 검증된 사용자 정보는 `scope["user"]`에 설정되며, Consumer에서 `self.scope.get("user")`로 접근할 수 있습니다.

---

## O/X 문제

### 12. WebSocket은 HTTP와 달리 연결이 지속되므로, 연결 시점에 한 번만 인증하는 것이 일반적이다.

**정답**: O  
**해설**: WebSocket은 연결이 지속되므로 연결 시점에 한 번만 인증하는 것이 일반적입니다. 연결 후 인증 토큰이 만료되거나 변경되는 경우를 처리해야 합니다.

---

### 13. scope 객체는 연결당 하나만 존재하며, 연결 종료까지 유지된다.

**정답**: O  
**해설**: scope 객체는 연결 수립 시 한 번 생성되어 연결 종료까지 유지되며, ASGI 애플리케이션과 미들웨어에서 공유됩니다.

---

### 14. JWT의 signature는 header와 payload를 비밀키로 서명한 값으로, 토큰의 무결성을 검증하는 데 사용된다.

**정답**: O  
**해설**: JWT의 signature는 헤더와 페이로드를 비밀키로 서명한 값으로, 토큰의 무결성을 검증하는 데 사용됩니다. Base64Url로 인코딩되어 있으며, 헤더에 명시된 알고리즘으로 생성됩니다.

---

### 15. Consumer 패턴에서 connect() 메서드는 클라이언트로부터 메시지를 받을 때 호출된다.

**정답**: X  
**해설**: `connect()` 메서드는 WebSocket 연결이 수립될 때 호출되며, 인증 검증, 초기 설정 등을 수행합니다. 메시지를 받을 때는 `receive()` 메서드가 호출됩니다.

---

## 서술형 문제

### 16. WebSocket 인증의 특수성을 설명하세요.

**정답**:  
WebSocket은 HTTP와 달리 연결이 지속되므로, 연결 시점에 한 번만 인증하는 것이 일반적입니다. 인증에 필요한 쿠키나 헤더는 HTTP Upgrade 요청의 초기 헤더에서만 추출 가능하며, 연결 수립 후에는 헤더가 없습니다. 따라서 미들웨어에서 초기 헤더에서 쿠키를 추출하여 JWT 토큰을 검증하고, 검증된 사용자 정보를 scope["user"]에 설정합니다.

**해설**: WebSocket의 지속 연결 특성으로 인해 인증은 연결 시점에만 수행되며, 이후 토큰 만료나 변경에 대한 처리가 필요합니다.

---

### 17. ASGI scope 객체의 주요 필드를 설명하세요.

**정답**:  
scope 객체의 주요 필드는 다음과 같습니다:
- `type`: 연결 타입 ("http", "websocket", "lifespan")
- `path`: 요청 경로 (예: "/ws/realtime-stt/")
- `headers`: HTTP 헤더 리스트 (바이트 튜플 형식)
- `client`: 클라이언트 주소 튜플 (ip, port)
- `server`: 서버 주소 튜플 (ip, port)
- `user`: 인증된 사용자 객체 (미들웨어에서 설정)

**해설**: scope 객체는 연결에 대한 모든 정보를 담은 딕셔너리로, ASGI 애플리케이션과 미들웨어 간 데이터를 공유하는 데 사용됩니다.
