# gRPC 스트리밍 STT 문제

## 객관식 문제

### 1. 실시간 STT에서 사용하는 gRPC 통신 방식은?

① Unary RPC  
② Server Streaming  
③ Client Streaming  
④ Bidirectional Streaming  

**정답**: ④  
**해설**: 실시간 STT는 Bidirectional Streaming을 사용합니다. 클라이언트와 서버가 독립적으로 여러 메시지를 주고받을 수 있어 실시간 오디오 전송과 결과 수신이 가능합니다.

---

### 2. Protocol Buffer의 장점이 아닌 것은?

① JSON보다 작은 크기  
② 파싱 속도가 빠름  
③ 브라우저에서 직접 호출 가능  
④ 강력한 타입 시스템  

**정답**: ③  
**해설**: Protocol Buffer는 바이너리 형식이므로 브라우저에서 직접 호출할 수 없습니다. gRPC는 HTTP/2 기반이지만 브라우저 호환성은 제한적입니다.

---

### 3. gRPC 클라이언트에서 서버의 메서드를 호출하기 위한 프록시 객체는?

① channel  
② stub  
③ service  
④ client  

**정답**: ②  
**해설**: stub은 gRPC 클라이언트에서 서버의 메서드를 호출하기 위한 프록시 객체입니다. 서버의 서비스 정의에 따라 자동 생성됩니다.

---

### 4. 양방향 스트리밍에서 첫 번째 요청에 포함되는 것은?

① 오디오 데이터  
② 설정 정보 (RecognitionConfig)  
③ 인증 토큰  
④ 세션 ID  

**정답**: ②  
**해설**: 양방향 스트리밍에서 첫 번째 요청은 설정 정보(RecognitionConfig)를 포함하며, 이후 요청은 오디오 데이터를 포함합니다.

---

### 5. gRPC가 HTTP/2의 멀티플렉싱을 활용하여 하나의 연결에서 여러 호출을 동시에 수행하는 기능은?

① 스트리밍  
② 멀티플렉싱  
③ 라운드로빈  
④ 로드밸런싱  

**정답**: ②  
**해설**: 멀티플렉싱은 하나의 연결에서 여러 gRPC 호출을 동시에 수행할 수 있는 기능으로, HTTP/2의 멀티플렉싱을 활용합니다.

---

### 6. STT 결과에서 아직 최종 확정되지 않은 임시 인식 결과를 의미하는 것은?

① final  
② interim  
③ pending  
④ processing  

**정답**: ②  
**해설**: interim은 중간 결과로, STT 처리 중 아직 최종 확정되지 않은 임시 인식 결과입니다. final은 최종 확정된 결과입니다.

---

### 7. gRPC 클라이언트와 서버 간의 연결을 나타내는 객체는?

① stub  
② channel  
③ connection  
④ stream  

**정답**: ②  
**해설**: channel은 gRPC 클라이언트와 서버 간의 연결을 나타냅니다. 호스트와 포트 정보를 포함하며, 여러 stub이 하나의 channel을 공유할 수 있습니다.

---

## 빈칸 채우기

### 8. gRPC는 (    ) 기반으로 동작하며, 단일 연결로 다중 요청을 처리할 수 있습니다.

**정답**: HTTP/2  
**해설**: gRPC는 HTTP/2 기반으로 동작하며, HTTP/2의 멀티플렉싱을 활용하여 단일 연결로 다중 요청을 처리할 수 있습니다.

---

### 9. Protocol Buffer 메시지는 (    ) 파일에 정의되며, 이를 컴파일하여 Python 코드를 생성합니다.

**정답**: .proto  
**해설**: `.proto` 파일에 메시지 구조를 정의하고, `grpc_tools.protoc`를 사용하여 Python 코드(`speech_pb2.py`, `speech_pb2_grpc.py`)를 생성합니다.

---

### 10. gRPC 양방향 스트리밍에서 첫 번째 요청은 (    )을 포함하고, 이후 요청은 (    )을 포함합니다.

**정답**: 설정, 오디오 데이터  
**해설**: 첫 번째 요청은 RecognitionConfig 설정 정보를 포함하고, 이후 요청은 audio_content 오디오 데이터를 포함합니다.

---

### 11. STT 결과에서 (    ) 결과는 변경될 수 있지만, (    ) 결과는 변경되지 않습니다.

**정답**: interim, final  
**해설**: interim(임시) 결과는 아직 최종 확정되지 않아 변경될 수 있지만, final(최종) 결과는 확정되어 변경되지 않습니다.

---

### 12. gRPC 클라이언트에서 SSL/TLS 보안 채널을 생성할 때 사용하는 함수는 (    )입니다.

**정답**: grpc.ssl_channel_credentials()  
**해설**: `grpc.ssl_channel_credentials()`를 사용하여 SSL/TLS 보안 채널을 생성하고, `grpc.aio.secure_channel()`로 보안 채널을 생성합니다.

## O/X 문제

### 13. gRPC는 REST API와 달리 스트리밍을 지원하므로 실시간 통신에 적합하다.

**정답**: O  
**해설**: gRPC는 양방향 스트리밍을 지원하므로 실시간 STT와 같은 실시간 통신에 적합합니다. REST API는 요청-응답 모델만 지원합니다.

---

### 14. Protocol Buffer는 JSON보다 크기가 크지만 가독성이 좋다.

**정답**: X  
**해설**: Protocol Buffer는 JSON보다 작은 크기이며 바이너리 형식이므로 가독성은 떨어집니다. 하지만 효율적이고 파싱 속도가 빠릅니다.

## 서술형 문제

### 15. gRPC의 4가지 통신 방식을 설명하세요.

**정답**:  
gRPC는 4가지 통신 방식을 지원합니다:
1. **Unary RPC**: 단일 요청-응답 패턴. 클라이언트가 하나의 요청을 보내고 서버가 하나의 응답을 반환합니다.
2. **Server Streaming**: 서버 스트리밍. 클라이언트가 하나의 요청을 보내면 서버가 여러 개의 응답을 스트림으로 전송합니다.
3. **Client Streaming**: 클라이언트 스트리밍. 클라이언트가 여러 개의 요청을 스트림으로 보내고 서버가 하나의 응답을 반환합니다.
4. **Bidirectional Streaming**: 양방향 스트리밍. 클라이언트와 서버가 독립적으로 여러 메시지를 주고받을 수 있습니다. 실시간 STT는 이 방식을 사용합니다.

**해설**: 각 통신 방식은 서로 다른 사용 사례에 적합하며, 실시간 STT는 양방향 스트리밍을 사용합니다.

---

### 16. Protocol Buffer의 특징을 설명하세요.

**정답**:  
Protocol Buffer는 구조화된 데이터를 직렬화하는 방법으로, 다음과 같은 특징을 가집니다:
1. **효율적**: JSON보다 작은 크기로 데이터를 표현합니다.
2. **빠름**: 파싱 속도가 빠릅니다.
3. **타입 안전**: 강력한 타입 시스템을 제공합니다.
4. **버전 호환**: 필드 추가/삭제 시 호환성을 유지할 수 있습니다.

**해설**: Protocol Buffer는 gRPC의 기본 직렬화 방식으로, 효율성과 성능에 최적화되어 있습니다.
