# 설정 관리 및 통합 문제

## 객관식 문제

### 1. RealtimeSTTConfig 모델에서 API 키는 어떻게 저장되나요?

① 평문으로 저장  
② 암호화하여 저장  
③ 해시로 저장  
④ 압축하여 저장  

**정답**: ②  
**해설**: API 키는 민감한 정보이므로 데이터베이스에 저장할 때 암호화해야 합니다. `shared_kernel.utils.encryption` 모듈의 `encrypt` 함수를 사용하여 암호화합니다.

---

### 2. 활성 설정 관리의 원칙은?

① 여러 설정을 동시에 활성화 가능  
② 한 번에 하나의 활성 설정만 사용  
③ 활성 설정이 없어도 동작 가능  
④ 모든 설정이 항상 활성화  

**정답**: ②  
**해설**: 시스템은 한 번에 하나의 활성 설정만 사용하는 단일 활성 원칙을 따릅니다. 새 설정 활성화 시 기존 활성 설정이 자동으로 비활성화됩니다.

---

### 3. 설정을 활성화할 때 수행하는 작업은?

① 현재 설정만 활성화  
② 다른 모든 설정을 비활성화한 후 현재 설정 활성화  
③ 모든 설정을 활성화  
④ 설정을 삭제  

**정답**: ②  
**해설**: 설정을 활성화할 때는 먼저 다른 모든 설정을 비활성화(`deactivate_all()`)한 후 현재 설정을 활성화합니다. 이를 통해 단일 활성 원칙을 보장합니다.

---

### 4. Repository 패턴의 목적은?

① 데이터베이스 쿼리 최적화  
② 데이터 접근 추상화  
③ 트랜잭션 관리  
④ 캐싱  

**정답**: ②  
**해설**: Repository 패턴은 데이터 접근을 추상화하여 비즈니스 로직과 데이터 접근 로직을 분리합니다.

---

### 5. 전체 시스템 통합 흐름에서 STT 처리 태스크가 시작되는 시점은?

① WebSocket 연결 수립 시  
② start 메시지 수신 시  
③ 오디오 청크 수신 시  
④ end 메시지 수신 시  

**정답**: ②  
**해설**: `start` 메시지를 받으면 세션을 초기화하고 SessionContext를 생성한 후, STT 처리 태스크를 시작합니다.

---

## 빈칸 채우기

### 6. API 키는 (    ) 함수로 암호화하고, (    ) 함수로 복호화합니다.

**정답**: encrypt, decrypt  
**해설**: `encrypt` 함수로 API 키를 암호화하여 저장하고, 사용 시 `decrypt` 함수로 복호화합니다.

---

### 7. RealtimeSTTConfig 모델의 (    ) 필드는 STT 제공업체를 나타냅니다.

**정답**: provider  
**해설**: `provider` 필드는 STT 제공업체(DAGLO, NAVER)를 나타내며, CharField로 저장됩니다.

---

### 8. 활성 설정을 조회하는 메서드는 (    )입니다.

**정답**: get_active  
**해설**: `get_active()` 메서드는 `is_active=True`인 설정을 조회하여 반환합니다.

---

### 9. 전체 시스템 통합 흐름에서 오디오 형식 변환은 (    ) 단계에서 수행됩니다.

**정답**: 오디오 변환  
**해설**: 오디오 형식 변환은 오디오 스트림을 받은 후 STT 서버로 전송하기 전에 WebM을 LINEAR16 PCM으로 변환하는 단계에서 수행됩니다.

---

### 10. 재시작 시나리오에서 기존 Queue는 (    )하고, 새로운 Queue를 (    )해야 합니다.

**정답**: 종료, 생성  
**해설**: asyncio.Queue는 한 번 종료되면 재사용할 수 없으므로, 재시작 시 기존 Queue를 종료하고 새로운 Queue를 생성해야 합니다.

---

## O/X 문제

### 11. API 키는 데이터베이스에 평문으로 저장해도 된다.

**정답**: X  
**해설**: API 키는 민감한 정보이므로 데이터베이스에 저장할 때 반드시 암호화해야 합니다. 평문 저장 시 유출 위험이 있습니다.

---

### 12. Repository 패턴을 사용하면 데이터 접근 로직과 비즈니스 로직을 분리할 수 있다.

**정답**: O  
**해설**: Repository 패턴은 데이터 접근을 추상화하여 비즈니스 로직과 데이터 접근 로직을 분리합니다. 이를 통해 테스트 용이성과 유지보수성이 향상됩니다.

---

## 서술형 문제

### 13. 단일 활성 원칙의 이유와 구현 방법을 설명하세요.

**정답**:  
단일 활성 원칙은 한 번에 하나의 활성 설정만 사용하는 원칙입니다.

**이유**:
- 설정 충돌 방지
- 명확한 동작 보장

**구현 방법**:
1. 설정을 활성화할 때 `deactivate_all()` 메서드를 호출하여 다른 모든 설정을 비활성화합니다.
2. 그 후 현재 설정을 활성화합니다.
3. 트랜잭션(`@transaction.atomic`)을 사용하여 원자성을 보장합니다.

**해설**: 단일 활성 원칙을 통해 시스템이 항상 하나의 명확한 설정을 사용하도록 보장합니다.
