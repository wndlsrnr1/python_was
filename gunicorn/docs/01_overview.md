# 1장: 개요 및 왜 필요한가

## 1.1 Gunicorn이란?

**Gunicorn**(Green Unicorn)은 Python 웹 애플리케이션을 실행하기 위한 **WSGI HTTP 서버**입니다.

### Spring/Tomcat과의 비교

Spring 개발자라면 다음과 같이 이해하면 됩니다:

| Spring/Tomcat | Python/Gunicorn |
|--------------|-----------------|
| Tomcat (서블릿 컨테이너) | Gunicorn (WSGI 서버) |
| WAR 파일 배포 | Python 모듈/패키지 배포 |
| `server.xml` 설정 | `gunicorn.conf.py` 설정 |
| 스레드 풀 모델 | 프로세스 기반 워커 모델 |

**핵심 차이점**: Tomcat은 Java 서블릿을 실행하는 컨테이너이고, Gunicorn은 Python WSGI 애플리케이션을 실행하는 서버입니다.

## 1.2 왜 필요한가?

### 개발 서버의 한계

Django나 FastAPI를 개발할 때 다음과 같이 실행해봤을 것입니다:

```bash
# Django
python manage.py runserver

# FastAPI
uvicorn main:app --reload
```

이 명령어들은 **개발용 서버**입니다. 개발 서버의 문제점:

1. **단일 스레드**: 한 번에 하나의 요청만 처리
2. **성능 부족**: 동시 접속자 수가 많으면 응답 지연
3. **안정성 부족**: 프로덕션 환경에서 충돌 시 복구 불가
4. **보안 취약**: 개발 편의 기능이 포함되어 있어 보안 위험

### 프로덕션 환경의 요구사항

실제 서비스를 운영하려면:

- **동시성 처리**: 여러 요청을 동시에 처리
- **안정성**: 프로세스가 죽어도 자동 재시작
- **성능**: 최적화된 요청 처리
- **모니터링**: 로그, 메트릭 수집

이러한 요구사항을 만족하는 것이 **Gunicorn**입니다.

## 1.3 Gunicorn의 역할

Gunicorn은 다음과 같은 역할을 합니다:

1. **HTTP 요청 수신**: 클라이언트로부터 HTTP 요청을 받음
2. **WSGI 애플리케이션 호출**: Python 애플리케이션의 WSGI 인터페이스를 호출
3. **응답 전송**: 애플리케이션의 응답을 클라이언트에 전송
4. **프로세스 관리**: 여러 워커 프로세스를 관리하여 동시성 확보

### 아키텍처 개요

```
클라이언트 요청
    ↓
Gunicorn (마스터 프로세스)
    ↓
워커 프로세스들 (Worker 1, 2, 3, ...)
    ↓
Django/FastAPI 애플리케이션
    ↓
응답 반환
```

이 구조는 Spring의 Tomcat이 여러 스레드로 요청을 처리하는 것과 유사하지만, **프로세스 기반**이라는 차이가 있습니다.

## 1.5 도움말: 궁금한 것들

이 섹션에서는 앞서 언급된 용어들에 대해 간단히 설명합니다. 자세한 내용은 이후 챕터에서 다룹니다.

### 워커 프로세스?

**워커 프로세스**는 실제로 HTTP 요청을 처리하는 독립적인 프로세스입니다. Gunicorn은 마스터 프로세스가 여러 워커 프로세스를 관리하는 구조로 동작합니다. Spring/Tomcat의 스레드 풀과 유사하지만, 프로세스는 메모리를 공유하지 않아 더 안정적입니다. 자세한 내용은 **04_worker_model.md**에서 다룹니다.

### WSGI 인터페이스?

**WSGI**(Web Server Gateway Interface)는 Python 웹 애플리케이션과 웹 서버 간의 표준 통신 규약입니다. Spring의 서블릿 스펙과 유사한 역할을 하며, 서버와 애플리케이션을 분리하여 호환성을 보장합니다. Gunicorn은 이 WSGI 규약을 통해 Django 등의 애플리케이션과 통신합니다. 자세한 내용은 **02_wsgi_asgi_protocol.md**에서 다룹니다.

### 매트릭?

**매트릭**(Metric)은 서버의 상태를 측정하는 지표입니다. 예를 들어, 초당 요청 수(RPS), 응답 시간, 메모리 사용량, CPU 사용률 등을 의미합니다. 프로덕션 환경에서는 이러한 매트릭을 수집하여 서버의 성능과 상태를 모니터링합니다. Spring Boot Actuator와 유사한 개념입니다.

### 자동 재시작 원리?

Gunicorn의 **마스터 프로세스**는 워커 프로세스들을 지속적으로 감시합니다. 워커가 예기치 않게 종료되면(크래시 등), 마스터 프로세스가 이를 감지하고 자동으로 새로운 워커를 생성합니다. 이는 Spring Boot의 자동 재시작 기능과 유사하지만, 프로세스 레벨에서 동작합니다. 자세한 내용은 **04_worker_model.md**에서 다룹니다.

### 동시성 처리?

**동시성 처리**는 여러 요청을 동시에 처리하는 능력입니다. Gunicorn은 여러 워커 프로세스를 실행하여 동시성을 확보합니다. 예를 들어, 4개의 워커가 있으면 최대 4개의 요청을 동시에 처리할 수 있습니다. Spring/Tomcat의 스레드 풀과 유사하지만, 프로세스 기반으로 동작합니다. 자세한 내용은 **04_worker_model.md**에서 다룹니다.
